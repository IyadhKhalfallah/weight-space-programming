# weight-space-programming

Experiments in **editing and writing machine-learning models directly**, without gradient descent:
fixing trained models by changing a few weights, adding rules inside a network, and writing models from scratch with zero labels.

Inspired by [Sparks of Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/) (MIT CSAIL, 2026).
The write-up with all results and charts is in [`article/article.md`](article/article.md).

**Short version:** on classic and small models (logistic regression, MLPs, trees, a small RL agent) editing works, and a hand-written
XGBoost model reached AUC 0.809 on rain forecasting with zero labels (trained on 2.5 years: 0.839), tested on data after the author's
knowledge cutoff. On a CNN, edits removed a shortcut but couldn't add a missing skill. On a 0.8B LLM, I found related directions
but my own edit didn't reproduce the published effect.

## Setup

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
# LLM experiments only (Apple Silicon):
.venv/bin/pip install -r requirements-llm.txt
```

`./py.sh script.py` runs a script with the repo on `PYTHONPATH` (and, on macOS, points XGBoost at PyTorch's bundled OpenMP).
Run everything from the repo root.

## The `wsl` CLI

A small toolkit to inspect a model, apply edits as reversible patches, and check them for regressions per data slice.
The base model is never modified: the current model = base + active patches.

```bash
./py.sh demo/make_demo.py      # trains a fraud model on biased data + writes 100k rows of recent traffic

./wsl.sh init    --ws demo/ws --model demo/fraud_model --data demo/traffic.csv --label is_fraud --slices currency,gift_card
./wsl.sh eval    --ws demo/ws                 # overall + per-slice metrics
./wsl.sh effects --ws demo/ws                 # how much each input moves the score
./wsl.sh units   --ws demo/ws --col currency --value BRL   # hidden units that behave differently on a slice
./wsl.sh ops                                  # available edit operations
./wsl.sh try     --ws demo/ws demo/edits/brl_calibrated.json   # dry run: before/after + regression check
./wsl.sh commit  --ws demo/ws demo/edits/brl_calibrated.json -m "calibrate BRL to its real risk"
./wsl.sh commit  --ws demo/ws demo/edits/giftcard_rule.json  -m "rule: gift card AND > \$500"
./wsl.sh info    --ws demo/ws                 # model + patch history
./wsl.sh revert  --ws demo/ws 1               # exact undo
./wsl.sh export  --ws demo/ws out.pt2 --format torch
```

Edit ops (JSON): `set_input_like`, `shrink_input_toward`, `scale_input`, `set_weights`, `project_out`, `add_input`, `add_rule`.
`add_rule` adds a small gated block (conditions → AND gate → output shift) that only fires when its conditions hold.

**Import / export**

| Format | Import | Export |
|---|---|---|
| PyTorch | TorchScript; `state_dict` (weights-only; give `--layout` if it has BatchNorm); pickled module with `--trust --code` | `torch.export` (`.pt2`) or TorchScript |
| scikit-learn | `LogisticRegression`, `MLPClassifier/Regressor`, pipelines with `StandardScaler` (folded in) | same estimator types (no rule blocks) |
| XGBoost | edited as JSON directly (see `experiments/e3_trees.py`); written from scratch with `wsl/xgb_write.py` | stock XGBoost JSON |

Supported layers: Linear, ReLU, Tanh, Sigmoid, BatchNorm1d (folded), Dropout/Identity/Flatten. Tasks: binary, multi-class, regression.

## Experiments

Each starts from a model with a realistic flaw (or no model at all), and is measured on new data.
The fraud, router and delivery datasets are **synthetic**, generated by the scripts with a known flaw built in.

| Script | Model | What happens | Result |
|---|---|---|---|
| `demo/` | PyTorch MLP (fraud) | currency bias fixed (32 weights); gift-card rule added (23 weights) | BRL false flags 7.2% → 2.0%; scam caught 10% → 98% |
| `demo/make_router_demo.py` | PyTorch 4-class router | outdated routing habit removed; takeover rule added | takeover tickets 2.6% → 95.8%; other logits change < 1e-7 |
| `experiments/e1_sklearn.py` | sklearn LogReg + MLP | currency bias | flags 6.8% → 2.0% (LogReg, 1 coefficient); 5.7% → 1.6% (MLP) |
| `experiments/e2_regression.py` | sklearn + PyTorch regressors | outdated zone delay + new construction | MAE 5.7 → 3.2 min |
| `experiments/e3_trees.py` | GradientBoosting, RandomForest, XGBoost | currency shortcut via split thresholds / appended tree | flags ~6.5% → ~1.5% |
| `experiments/e4_rl.py` | RL policy (Catch) | agent learned a rendering bug; hand-written circuit grafted in | score −0.1 → +19.3 (original +19.4) |
| `experiments/e5_cnn.py`, `e5b_cnn_write_skill.py` | CNN | camera-stamp shortcut removed; missing skill partly hand-written | shortcut gone, but accuracy 52% → 71% only |
| `experiments/e6_xgb_from_scratch.py` | XGBoost written by hand | breast cancer, zero labels | AUC 0.972 vs 0.985 trained (famous dataset: may be memorised) |
| `experiments/e7_*.py` | XGBoost written by hand | rain tomorrow, 10 EU cities, tested Jul–Oct 2026 | AUC 0.809 (v1, zero labels) / 0.815 (v3) vs 0.839 trained on 2.5 years |

**Reproduce the CLI-based ones** (after running the generating script):

```bash
# E2: regression fixes
F=distance_km,items,rush_hour,rain,driver_exp,zone_A,zone_B,zone_C,zone_D; G=zone=zone_A,zone_B,zone_C,zone_D
./wsl.sh import-sklearn experiments/e2/delivery_sklearn.joblib --out experiments/e2/m_sk --features $F --group $G --trust
./wsl.sh import-torch experiments/e2/delivery_torch.pt --out experiments/e2/m_torch --features $F --group $G --task regression
for k in sk torch; do
  ./wsl.sh init --ws experiments/e2/ws_$k --model experiments/e2/m_$k --data experiments/e2/deliveries.csv --label minutes --slices zone,long_trip
  ./wsl.sh commit --ws experiments/e2/ws_$k experiments/e2/edits/fix_$k.json -m "remove old zone-D delay, add zone-A construction"
done

# Router (multi-class)
./wsl.sh import-torch demo/router/router_script.pt --out demo/router/model \
  --features mentions_payment,mentions_refund,mentions_error,mentions_login,suspicious_login,msg_length,account_age,prev_tickets,plan_free,plan_pro,plan_enterprise \
  --group plan=plan_free,plan_pro,plan_enterprise --classes billing,technical,account,security
./wsl.sh init --ws demo/router/ws --model demo/router/model --data demo/router/tickets.csv --label queue --slices plan,takeover_pattern
./wsl.sh commit --ws demo/router/ws demo/router/edits/enterprise_plan.json -m "enterprise like other plans"
./wsl.sh commit --ws demo/router/ws demo/router/edits/takeover_rule.json -m "suspicious login AND payment -> security"
```

Rain experiment order: `e7_fetch_weather.py` (optional, data is included) → `e7_rain.py` → `e7_diagnose.py` → `e7_validate.py` → `e7_final.py`.
The hand-written models are readable JSON programs: `experiments/e7/rain_program*.json`, `experiments/e6/level0_program.json`.

`proofs/` has the first small proofs: writing a game-playing net from scratch (Catch), fixing a bias, adding a rule layer.

## LLM experiments (`llm/`)

Qwen3.5-0.8B with MLX on Apple Silicon. Run from inside `llm/`, after downloading the models:

```bash
cd llm
hf download Qwen/Qwen3.5-0.8B --local-dir models/Qwen3.5-0.8B
hf download RikiyaT/Qwen3.5-0.8B-weight-space-programming --local-dir models/Qwen3.5-0.8B-weight-space-programming
../py.sh discover.py   # find candidate directions from the base model only
../py.sh search.py     # search layers/directions, write an edit to models/loop
../py.sh causal.py     # teacher-forced P(</think>) for base, published edit, own edit
```

Memory is capped at 6 GB in the scripts. Logs of my runs are in `llm/results/`. The published edit raises P(`</think>`) about 29×; mine about 1.2×.
